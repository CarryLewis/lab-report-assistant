# 文档结构识别模块开发纲领

- 文件性质：文档结构识别、规范化与后续规则训练的总体依据
- 版本：1.0
- 生效日期：2026-10-24
- 状态：按首轮文档审查与用户确认的总体设计建立，后续开发与验证须遵循
- 适用范围：DOCX、PDF、Markdown、HTML 及其他作业文档的结构解析、层级推断、图表关联、规范化输出、AI 检索切块、样本标注、规则训练和质量评测

## 1. 目标与治理

本模块把学生作业转换为可定位、可解释、可回溯的规范结构树，使教师界面、AI 分析、引用验证、图表分析和证据定位使用同一份文档结构。

本文件是结构识别模块后续开发、样本标注和规则调整的上位依据。实现细节可以迭代，但不得绕过以下原则：

- 优先使用文档已有语义，不以视觉外观替代语义结构。
- 规则先于 AI；AI 只补充规则无法确定的部分。
- 不确定时保留未知状态，不强行生成层级。
- 所有推断均保存证据、置信度、规则版本和来源位置。
- 原始内容、解析结果、规范结构和人工修订分别保存，不覆盖原始文档。
- 结构识别只描述文档组织，不自动判断科学质量或给分。

需要改变结构类型、规则优先级、人工审核责任、输出契约或验证口径时，应先更新本纲领并记录版本。新增样本不得直接改变生产规则；必须先进入标注、评测和回归流程。

本纲领不是识别功能已经完成的声明。规则设计、样本标注、离线评测、试点验证和生产可用性必须分别说明。

## 2. 总体识别流程

结构识别采用以下固定阶段：

1. 输入登记与格式识别。
2. 原始文档块解析。
3. 显式语义与硬规则识别。
4. 视觉及上下文软规则识别。
5. 特殊对象组合与跨块关联。
6. AI 辅助处理歧义候选。
7. 冲突处理与置信度计算。
8. 生成规范结构树。
9. 从规范结构派生 Markdown、检索块和界面定位数据。
10. 执行结构完整性与可追溯性检查。

各阶段保留输入、输出、状态、失败原因和使用的规则版本，允许对同一文档重新运行及比较结果。

## 3. 原始解析与信号保留

解析器先忠实提取文档对象，不在此阶段提前决定标题或章节。

每个原始块至少保留：

- 稳定块标识；
- 文档版本标识；
- 块类型和原始文本；
- 页码及可用时的边界框；
- Word paragraph style、outline level、编号和列表层级；
- 字体、字号、粗体、斜体、对齐、缩进及段前段后距离；
- 分页符、分节符及页面位置；
- 表格、单元格、图片、图表、公式和文本框关系；
- Caption、书签、交叉引用及字段；
- 前一块、后一块及父容器关系；
- 原始文件中的对象或 XML 定位信息。

格式清洗、OCR 修正和字符归一化不得删除原始值。清洗值与原始值分字段保存。

## 4. 结构类型与规范标签

第一版使用受控标签集合，AI 和规则均不得在运行时随意创造类型：

- `document_title`
- `subtitle`
- `section_heading`
- `subsection_heading`
- `body_paragraph`
- `list_item`
- `figure`
- `figure_caption`
- `table`
- `table_caption`
- `equation`
- `equation_caption`
- `reference_section`
- `reference_entry`
- `footnote`
- `header_footer`
- `page_artifact`
- `unknown`

层级与类型分开保存。标题类型表示其作用，`level` 表示它在结构树中的深度。图题、表题、参考文献条目和页眉页脚不得被提升为章节标题。

## 5. 规则优先级

发生冲突时，默认采用以下优先顺序：

1. 原生语义和明确结构标签；
2. outline level、正式编号及自动 Caption 字段；
3. 经确认的课程或文档模板映射；
4. 多个相互支持的版式和上下文信号；
5. AI 基于限定上下文的分类；
6. 单一视觉特征。

低优先级结果不得静默覆盖高优先级结果。若高优先级信号本身明显异常，应保存冲突并进入复核，而不是直接丢弃原始信号。

### 5.1 硬规则

以下信号在无冲突时可直接采用：

- Word `Title`、`Heading 1` 至 `Heading 9`；
- Word outline level；
- HTML `h1` 至 `h6`；
- Markdown ATX 或 Setext 标题；
- 明确的多级编号关系；
- Word Caption、题注编号和交叉引用字段；
- 经项目确认并版本化的模板样式映射。

硬规则输出须标记为 `explicit`，并记录具体来源，例如 `word_style:Heading2`。

### 5.2 软规则

缺少原生语义时，系统可组合以下信号生成候选：

- 文本长度和是否为完整句；
- 整行粗体或与正文不同的字重；
- 字号相对正文基线的变化；
- 段前、段后间距；
- 对齐、缩进及页面位置；
- 是否位于文档或新页开头；
- 是否使用常见章节名称；
- 是否与其他候选共享稳定版式；
- 后续是否存在足够的从属内容；
- 与相邻已确认标题的层级关系；
- 编号深度和章节序列。

粗体、字号、居中、关键词中的任何单一信号都不足以确认标题。软规则必须保存命中信号、反向信号和计算结果。

## 6. 标题与层级判定

系统先判断“是否为标题”，再判断“标题层级”，不得把两个问题合并为一次自由生成。

标题候选至少满足多个相互支持的信号，并能合理解释其后的内容范围。层级判定优先使用 outline level 和编号；缺失时再比较全篇标题模式、字号、间距、章节范围及上下文。

基本约束包括：

- 一份文档原则上只有一个主标题；
- 子标题必须存在合理的上级标题；
- 不因版式变化随意跳级；
- 同类章节应尽量使用一致层级；
- 章节结束可以回到更高层级，不视为跳级错误；
- 无法区分正文强调与标题时，保留候选或 `unknown`，不自动升级。

实验报告中的 Introduction、Methods、Results、Discussion、Conclusion、References 等词只作为支持信号，不作为绝对规则。

## 7. 图、表、公式与题注关联

特殊对象必须以组合对象处理，不能只抽取图片或表格本体。

图对象应关联：

- 图片或图表本体；
- 图号；
- 图题；
- 替代文本；
- 图内可读文字；
- 正文引用；
- 邻近解释段；
- 页码和边界框。

表对象应关联：

- 表号和表题；
- 单行或多行表头；
- 行标题、单位和数据单元格；
- 合并单元格；
- 表下注释；
- 正文引用和邻近解释段；
- 跨页关系。

题注在对象上方或下方均可成为候选。对象距离、编号格式、文档一致性、Caption 字段和正文引用共同决定关联。缺少题注时标记为未命名对象，不由 AI 编造题注。

同一数据在多个表格或图表中重复出现时，分别保留对象，并建立 `derived_from`、`summarizes` 或 `duplicates_data` 等关系，不自行删除内容。

## 8. 参考文献与其他易误判区域

进入已确认的参考文献章节后，作者名、年份、斜体期刊名和 DOI 不得被当作子标题。每条文献形成独立 `reference_entry`，跨段或跨页条目应在保留原始块的同时建立组合关系。

以下对象默认不参与正文标题树，除非有明确证据：

- 页眉和页脚；
- 页码；
- 封面元数据；
- 图表内部标签；
- 表格单元格中的大号或粗体文字；
- 水印、装饰文字和 OCR 噪声；
- 教师批注和修订标记。

## 9. AI 辅助推断边界

AI 只处理规则输出的歧义候选，不直接接收丢失版式信息的全文并自由重建结构。

AI 输入应包括：

- 当前候选块及必要的前后块；
- 原始格式与版面信号；
- 已确认的上级标题和当前结构树；
- 硬规则及软规则结果；
- 允许选择的标签和层级；
- 冲突信息及必须保留的原始事实。

AI 输出必须符合固定结构，只能选择受控标签，并说明支持证据、反向证据和不确定性。AI 不得：

- 覆盖明确且无冲突的原生语义；
- 根据内容质量改变文档结构；
- 编造不存在的标题、图题、表题或章节；
- 把预期的实验报告结构当成学生实际写出的结构；
- 以模型自报置信度代替规则计算和样本评测。

## 10. 冲突处理与置信度

每个规范节点至少记录：

- `classification_source`：`explicit`、`rule_inferred`、`ai_inferred` 或 `human_corrected`；
- `confidence`：数值或等级；
- `evidence`：命中的规则及原始定位；
- `counter_evidence`：相反信号；
- `rule_version`；
- `model_version`，如使用 AI；
- `review_status`。

首轮建议阈值：

- `0.85–1.00`：自动采用；
- `0.65–0.84`：暂时采用并进入抽样复核；
- `0.40–0.64`：保留为待验证候选；
- `< 0.40`：使用正文或 `unknown`，不强制判断。

阈值仅是初始设计，必须在标注样本上校准。不同对象类型可以使用不同阈值，高风险结构操作应优先提高精确率。

## 11. 规范结构与派生输出

结构识别的事实来源是规范文档树，而不是 Markdown。规范节点至少包含：

```json
{
  "id": "sec-results",
  "type": "section_heading",
  "level": 1,
  "text": "Results",
  "heading_path": ["Results"],
  "source_block_ids": ["p-021"],
  "classification_source": "rule_inferred",
  "confidence": 0.91,
  "evidence": ["full_line_bold", "larger_than_body", "known_section_term"],
  "rule_version": "structure-rules-0.1"
}
```

Markdown、HTML、界面目录和 AI 检索块均由该结构树派生。Markdown 映射使用固定规则：

- 文档标题 → `#`
- 一级章节 → `##`
- 二级章节 → `###`
- 三级章节 → `####`
- 图题、表题和参考文献条目 → 对应对象内容，不用粗体模拟标题

派生输出不得反向覆盖规范结构。Markdown 转换失败不等于原始解析失败，应分别记录。

## 12. AI 检索切块与证据定位

检索切块优先服从结构边界，不使用固定字符数作为唯一边界。每个检索块至少附带：

- 文档及版本标识；
- 节点和父节点标识；
- `heading_path`；
- 块类型；
- 页码及边界框；
- 相关图、表、公式和题注标识；
- 前后块标识；
- 解析、规则及模型版本。

图表本体、题注、必要的数据表和直接解释段应尽量保持在同一检索单元或通过关系明确连接。任何 AI 建议必须能回到原始块和页面位置。

## 13. 结构完整性检查

每次识别完成后至少执行：

- 主标题数量检查；
- 标题层级连续性检查；
- 空章节和异常短章节检查；
- 标题与正文范围检查；
- 图表与题注关联检查；
- 表头和单位识别检查；
- 正文图表引用解析检查；
- 参考文献区域及条目边界检查；
- 原始块覆盖率检查；
- 规范节点到原始位置的可回溯检查；
- Markdown 与规范结构树的一致性检查。

检查发现异常时，保留可用的部分结果，并明确标记失败范围，不因局部问题丢弃整份文档。

## 14. 后续样本、训练与验证接口

后续引入的小样本应先形成独立标注集，不直接写入规则。每个样本至少保存：

- 原始文件和稳定样本标识；
- 文件来源类型和格式特征；
- 人工确认的结构树；
- 标题、层级、图表、题注、表头和参考条目的逐块标签；
- 歧义说明和标注理由；
- 当前规则输出；
- 错误类型；
- 审核人和标注版本。

样本应覆盖：

- 正确使用标题样式的文档；
- 仅依赖粗体、字号或空行的文档；
- 标题等级跳跃或编号错误；
- 图题和表题格式不一致；
- 跨页表格和跨页参考文献；
- 文本框、页眉页脚和复杂版式；
- 扫描 PDF、OCR 错误及混合语言；
- 内容完整但结构语义缺失的报告；
- 结构严重损坏或只能部分解析的报告。

验证集与规则开发集必须分离。规则调整后，对全部固定回归样本重新运行，不只验证触发本次调整的样本。

## 15. 评测指标与错误分类

至少分别评测：

- 标题识别精确率、召回率和 F1；
- 标题层级准确率；
- 章节边界准确率；
- 图题和表题识别准确率；
- 图表与题注关联准确率；
- 表头识别准确率；
- 参考文献条目边界准确率；
- 原始块覆盖率；
- 原始位置回溯成功率；
- Markdown 结构一致率；
- 人工纠正率及纠正原因。

错误至少分为：

- 解析缺失；
- 标题误报或漏报；
- 层级错误；
- 章节边界错误；
- 对象分类错误；
- 题注关联错误；
- 参考文献边界错误；
- AI 覆盖明确规则；
- 输出转换错误；
- 页面定位错误。

不得用单一总体准确率掩盖高风险错误。将正文误判为标题、将图题误判为章节、将参考条目拆成标题等错误应单独报告。

## 16. 后续实施顺序

1. 定义原始块和规范结构树的数据契约。
2. 实现 DOCX 显式样式、outline level、编号、表格和媒体对象解析。
3. 建立 Markdown 及界面目录的确定性派生输出。
4. 建立软规则特征、规则版本和可解释证据。
5. 建立图表、题注、正文引用和参考文献关联。
6. 建立小样本标注格式、黄金集和回归测试。
7. 在规则基线稳定后引入受限 AI 歧义判断。
8. 根据保留验证集和教师复核结果校准阈值。

每次交付均说明实现阶段、规则版本、使用样本、评测结果、已知限制和人工复核要求。

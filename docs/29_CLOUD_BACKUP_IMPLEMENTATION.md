# iCloud／OneDrive 网盘备份：首轮实现与构建记录

后续版本决策（2026-11-05）：本功能与加权量表修复已整合为 **1.4.1 Beta 测试版**，主流稳定版仍为 **1.3.7**。以下保留首轮实现的历史记录；当前安装包与验收结果见 [1.4.1 测试版说明](31_RELEASE_1_4_1_BETA.md)。

日期：2026-11-04（Asia/Shanghai）。对应[接入设计规划](28_CLOUD_BACKUP_DESIGN_1_4_1.md)。当前程序版本沿用工作区的 1.3.7，本轮安装包位于独立的 `output/cloud-backup-preview/`，不是新的正式发布，也未覆盖既有 `output/installers/` 产物。

## 本轮实现

- 设置页新增“网盘备份”，提供 iCloud Drive 文件夹、OneDrive 客户端文件夹、OneDrive 账号三种目标，含中文和英文界面。
- 支持立即备份、应用运行期间每 15／60 分钟定时备份、状态刷新、备份历史和恢复独立副本。默认关闭定时备份，保存位置不会立即上传。
- 文件夹模式向 `Labwise Backups` 写入唯一命名快照，完整写入后改名；明确显示本机写入状态，不伪称云端传输完成。普通自选目录会标为自选备份目录。
- OneDrive 账号模式通过微软设备授权接入 Graph 应用专属文件夹，支持轮询、刷新、断开、历史分页、上传和下载。授权只保存在内存，退出后需要重新连接。
- 复用现有一致性备份与严格恢复校验；工作数据库保持本机保存。AI 密钥、网盘令牌和本机网盘设置不进入 ZIP。
- 目标和账号变更与传输互斥；失败保留上次成功记录与已有备份。调度器随服务启动，在服务关闭时收到停止信号。
- 静态资源白名单、启动资源检查、Docker 资源清单和 macOS 包内检查已接入新增文件。

代码入口：`cloud_backup.py`、`cloud-backup.js`、`cloud-backup.css`；本机 API 位于 `/api/pilot/cloud/`，由 `pilot_backend.py` 分派。

## 如何试用

1. 安装本轮独立目录中的 macOS Apple Silicon 试用包，先保存并保留原工作区备份。
2. 进入“设置”，找到“网盘备份”。选择 iCloud Drive 或 OneDrive 客户端文件夹，输入已经存在的本机网盘目录绝对路径；应用在其内建立 `Labwise Backups`。
3. 保存设置后点击“立即备份”。在 Finder 或 OneDrive 客户端确认实际云端上传状态；另一台兼容电脑上等待文件下载完成后，在历史中选择恢复。
4. 恢复建立独立目录，原工作区保留。关闭当前应用后，运行副本目录的“启动恢复副本.command”，核对资料并重新配置 AI 密钥。
5. 若需要定时备份，主动选择 15 或 60 分钟并保存。应用必须保持运行，且只备份已保存的批改内容。

OneDrive 账号模式还需维护者注册 Microsoft Entra 公共客户端，支持目标个人／学校账号，配置 `Files.ReadWrite.AppFolder` 委托权限，并在启动进程环境中提供公开应用 ID `LABWISE_ONEDRIVE_CLIENT_ID`。不能在应用内嵌入客户端秘密；学校可能限制设备授权或要求管理员同意。当前构建未注入正式应用 ID，账号连接按钮会保持不可用，文件夹模式仍可使用。教师不需要自行注册开发者应用。

首期通过受支持协议直接实现设备授权 HTTP 请求，尚未引入 MSAL；正式授权集成和系统钥匙串持久连接仍按设计 P2／P3 继续评估。

- Python：`.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`，118 项通过，其中新增网盘测试 14 项。
- JavaScript：现有 `tests/test_*.js` 共 10 个脚本通过；新增设置脚本语法检查通过。
- 新增测试使用临时资料目录与虚构 DOCX，验证文件夹备份恢复、资料保留、凭据排除、目标边界、损坏／超限备份、并发拒绝、授权轮询与刷新、远端历史分页、下载重定向不转发 Bearer、定时任务和 HTTP 来源限制。微软服务均采用模拟响应。
- 本机设置页实际检查通过目录保存、立即备份和历史展示。恢复确认弹窗阶段的浏览器自动化连接超时，未将该段 UI 流程标为通过；恢复后端与安装包恢复流程另有通过记录。
- macOS arm64 应用构建、包内依赖和隐藏启动窗口检查、临时签名完整性检查、DMG 校验通过。
- 包内 LibreOffice 实际转换、移动到其他路径后转换及签名保持检查通过。
- `packaging/smoke_macos.py` 完成 14 类安装验收，包含打包后两种文件夹目标的备份、历史与独立恢复，以及虚构报告确认、导出、重启保留资料和恢复副本重新打开。

构建使用 `LABWISE_BUILD_DIR=/private/tmp/labwise-cloud-preview-build` 和 `LABWISE_RELEASE_DIR=<项目>/output/cloud-backup-preview`。产物清单、SHA-256 与 `installation-smoke-test.json` 随独立安装包保存；安装包、虚构备份和临时数据不提交到公开源码。

## 已知范围与后续工作

- 尚未使用真实 iCloud 验证上传和异机下载，也未使用真实 OneDrive 账号／学校租户验证权限与文件往返。因此只能称为实现和隔离验证完成，不能称为真实网盘已全面验收。
- iCloud 采用用户目录模式，尚未增加原生目录选择器、文件协调／下载状态辅助层或 iCloud 应用容器。需要教师确认目录与文件实际可用。
- OneDrive 账号模式是会话级授权试用能力；需要正式应用注册配置和真实最小权限验证，再推进持续连接。未验收世纪互联等国家云。
- ZIP 最大 64 MiB、展开资料最大 256 MiB；当前仍使用完整快照和 Base64 内存传递。大容量流式处理和断点续传尚未实现。
- 传输在独立 HTTP 请求线程内执行，当前请求等待结果；不阻塞整个本机服务，但尚无可恢复任务 ID 或传输取消界面。关闭页面后可刷新状态／历史核对备份结果，不应假设请求中断代表操作未执行。
- 不提供应用退出后的后台备份、自动保留清理、应用级加密、跨版本迁移保证、跨设备合并或多人协作。两台电脑独立修改会形成分支。
- 本轮继续使用本机临时签名，未完成 Developer ID 签名与 Apple 公证；其他操作系统未验收。本轮未构建 Docker 镜像。

下一步优先完成真实 iCloud 异机恢复、配置受控 OneDrive 测试应用并验证个人与拟支持学校账号，再按规划推进原生目录体验、持续授权和大容量备份。

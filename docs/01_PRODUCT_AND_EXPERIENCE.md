# 产品与网站体验设计

## 产品要解决的问题

中国高校教师在批改英文 Lab Report 时，往往需要花大量时间阅读英文、理解学生的实验论述、对照评分细则，并将问题定位回原文。本产品将这些步骤整理为一个可查看、可审核、可编辑的工作台。

首个版本的价值不是替教师决定分数，而是帮助教师更快形成可靠判断。

## 首个 Demo 的用户路径

```text
进入课程 → 选择作业与 rubric → 上传报告 → 等待分析
→ 浏览报告结构 → 查看 rubric 建议与原文证据
→ 编辑、接受或拒绝建议 → 生成反馈摘要
```

任何页面和功能都应支持这条路径；不能缩短理解、对照、定位或确认步骤的功能，不进入首版。

## 页面轮廓

### 课程与作业页

教师从这里进入对应课程和作业。页面应显示课程名称、作业要求、当前 rubric 版本和报告列表。首版只需支持一门课程和一个作业类型，但结构上应保留未来增加课程的空间。

### 上传与分析页

教师上传可解析的 DOCX 报告，确认使用的作业要求和 rubric。系统要清楚显示分析状态，并在解析失败或文件不符合要求时说明原因与下一步。

### 批改工作台

这是产品的核心界面，应采用三部分布局：

- **结构区**：报告章节、结构树和中文概览；用于快速理解报告的主线。
- **原文区**：英文报告全文；能够定位并高亮与反馈相关的段落。
- **反馈区**：按照 rubric 呈现优点、问题、缺失项、证据与建议；教师在这里审核和编辑。

结构树或思维导图只承担浏览和定位功能，不单独作为评分判断。

### 输出页

教师确认后，系统生成清晰的反馈摘要，供教师保存、复制或带回现有教学平台。输出应反映教师最终确认的内容，而不是未经审核的 AI 原始建议。

## 每条反馈的最低信息

一条可供教师审核的建议至少应包含：

- 对应的作业要求或 rubric 条目；
- 结论类型：优点、需要改进、缺失内容或需教师核实；
- 英文原文中的具体段落或短引文；
- 简洁的中文解释；
- 教师操作：接受、编辑或拒绝。

没有证据的内容不能表现为确定性结论。

## 体验原则

- 先帮助教师理解，再给出建议；避免把复杂评分结果先塞给用户。
- 原文、rubric 和建议同时可见，减少页面来回跳转。
- 用清楚、克制的语言表达不确定性，不把猜测包装成事实。
- 保留教师最后决定权，并记录教师的修改。
- 对非英语母语教师优先提供中文解释，同时保留完整英文证据。

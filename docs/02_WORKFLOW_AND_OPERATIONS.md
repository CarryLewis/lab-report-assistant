# 教师工作流与运营设计

## 工作流总览

产品要嵌入教师现有批改工作，而不是要求教师改变正式评分制度。首个试点以“报告上传、分析、教师审核、反馈导出”为一轮完整工作。

```text
课程准备 → 上传/导入报告 → AI 辅助分析 → 教师审核
→ 输出正式反馈 → 收集使用反馈 → 改进下一轮
```

## 课程准备

课程负责人需要在每次作业开始前确认：

- 本次作业的题目和学生必须完成的内容；
- 使用的 rubric 及其版本；
- 可用的报告格式；
- 哪些教师能够查看和批改该课程资料；
- 输出反馈的格式和正式成绩仍在哪个系统中维护。

课程设置完成后不应随意修改；若 rubric 有变化，应创建新版本并明确适用范围。

## 一份报告的批改流程

1. 教师选择课程、作业和 rubric 后上传报告。
2. 系统解析报告并生成章节结构、中文概览和 rubric 候选建议。
3. 教师先查看结构和报告主线，再按 rubric 检查建议。
4. 教师点击证据，核对建议是否得到原文支持。
5. 教师接受、编辑或拒绝每条建议，并决定最终成绩与正式反馈。
6. 系统保存教师确认后的反馈，并导出供教学流程使用的摘要。

AI 分析出现故障、证据不足或报告解析异常时，教师仍可继续手动完成批改；系统应清楚标记未完成的分析，不应生成误导性的最终结论。

## 角色与责任

### 教师

使用分析结果理解报告，核对证据，编辑反馈并决定最终成绩。

### 课程负责人

维护题目要求、rubric、试点范围和教师访问权限；确认输出是否符合课程要求。

### 系统维护者

保障账号、资料、分析任务和系统运行；不以默认权限查看学生报告或教师反馈。

### 学校管理员

在需要时确认课程接入、教学平台衔接、数据处理安排和试点授权。

## 运营节奏

- **试点前**：准备作业要求、rubric、样本和教师培训材料。
- **试点中**：每周查看解析失败、证据问题和教师修改情况；快速修正明确的流程问题。
- **试点后**：与教师复盘节省的时间、建议质量和未解决的问题；决定继续、调整或扩大范围。

## 成功标准

试点成功不以“AI 自动给分”为标准，而看以下问题是否得到肯定回答：

- 教师是否更快读懂英文报告？
- 建议是否能回到可靠的原文证据？
- rubric 对照是否减少了遗漏？
- 教师是否愿意采用或修改后采用部分建议？
- 产品是否可以自然融入教师现有的正式批改流程？

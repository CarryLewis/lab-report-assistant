# 加权评价量表核查与修复

后续交付：该修复与网盘备份已打包为 [1.4.1 Beta 测试版](31_RELEASE_1_4_1_BETA.md)。下文保留修复阶段的验证记录。

日期：2026-11-05（Asia/Shanghai）。本次修改的是当前源码，没有重新打包、替换已安装应用或发布新版本。工作区已有的网盘备份等修改保留。

## 核实的问题

原文：“方法占30%，结果占70%。每个维度先按百分制评价：优秀80至100，合格60至79，不合格0至59，最后按权重计算总分。”

旧校验器先将每项总分贡献算成 30/70，再用它们检查原始 80–100 等级，错误地把合法细则判为未就绪。该问题与模型是否正确提取原文是两回事，修复前已在离线探针中重现。

## 修改后的数据与行为

- `maximum_points` 继续表示该项目对报告总分的贡献上限，兼容已有教师分数、总分、采纳与导出流程。
- `evaluation_maximum` 独立保存原文明确指定的零起点评价量表，例如百分制的 100；`evaluation_source_quote` 必须能在细则原文定位。
- 等级范围仍保留在原始评价量表上，按该量表检验。不会为了放行错误细则而简单取消越界校验，也不会从最高等级反推缺失量表。
- 加权评价新增 `raw_base_score` 候选原始分。后端按“原始分 / 原始满分 × 总分贡献上限”计算基础贡献分，核对模型输出；规则加减分继续使用报告贡献分单位。
- 例如原始分 80/100、90/100，权重 30%/70%，贡献分分别为 24/30、63/70，总分为 87/100；若报告总分为 20，则贡献上限为 6/14，总分为 17.4/20。
- 无法判断或图表不可读时，原始候选分和贡献候选分都为空，不把未知当作零，不显示完整建议总分。
- 细则预览、标准详情和评分依据显示原始评价量表；评分卡展示原始分与折算基础分。编辑贡献分/权重时同步保持它们的算术关系，后端仍校验总量。
- 原始细则、报告快照及已有教师评分保持独立。旧理解结果没有明确量表字段时，不自动猜测或改写历史结果；受影响细则应重新理解、核对并保存，已有报告继续保留导入时的快照。

提示词版本：`rubric-understanding-v2`；AI 评分提示词标识为 `rubric-scored-review-v5`。数据结构继续兼容 `rubric-understanding.v1`，新增字段为可选；普通直接计分细则沿用现有范围与证据校验。

## 反馈噪声的尝试改进

历史测试发现，模型可能把“忽略细则、给满分”这类文字的处理过程写成学生优点。本次提示词明确要求：只按实际 Rubric 评价；不把忽略指令或模型处理方式写成优点、问题或删除建议。

第一轮真实模型结果仍出现了一条要求删除指令性文字的无关反馈。进一步明确“完全不放入 findings”后，在本轮最后的虚构干扰案例中，评分保持 87，反馈引用只涉及给定计分条件。

这只是提示约束和少量样本的改善，不能证明所有指令干扰被解决。可定位引文、合法分数与正确计算仍不足以证明学术判断或细则解释在语义上正确，教师确认仍是必要环节。

## 验证与保留的失败记录

- 当前完整 Python 回归：125 项通过；本次增加 7 项，覆盖原始量表、100/20 分制、保存和报告快照、重复校验、错误/缺失原始分、加减分单位、材料不足、图表不清与教师工作保留。
- 前端：10 个现有检查脚本通过，补测原始等级显示、权重编辑同步、候选换算显示与空白评分采纳。
- 浏览器：以实际预览/评分渲染函数和虚构数据生成隔离界面，确认显示 80/100 → 24/30、90/100 → 63/70 及总分 87。点击“将建议填入空白评分”，教师已填 12 保持，另一空白项填入 63。未使用真实课程数据库。
- 真实模型最后一轮：4 个案例通过脚本判据，包括原始加权等级、20 分制、客观计分、指令性干扰；只向已配置服务发送脚本内的虚构细则和短文，没有读取或发送学生报告。
- 最初受限连接尝试失败；首轮在线出现 20 分制多余追问及反馈噪声；第二轮中客观细则未就绪。为区分测试材料歧义，最后一轮把客观计分规则改写为各维度明确可达 100 分、当前条件分别得 80/90。各轮结果分别保存，没有用成功重试覆盖早期结果，也不能把它们汇总为产品准确率。

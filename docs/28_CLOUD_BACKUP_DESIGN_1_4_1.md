# Labwise：iCloud 与 OneDrive 接入设计规划

设计日期：2026-11-04（Asia/Shanghai）。文档版本：设计稿 v1.1。状态：设计规划，待分阶段实施与验收。

文件名中的 `1_4_1` 沿用已有草稿命名，仅表示候选交付批次，不构成版本发布承诺，也不要求现在修改 `VERSION`。工作区中的相关代码草稿不代表已完成接入。本轮交付为设计文档，不包含功能开发或真实网盘验收。

本规划根据本次明确的 iCloud／OneDrive 接入需求，扩展[本机应用交付纲领](21_LOCAL_APP_DELIVERY.md)中的个人资料备份范围；本机优先、单教师工作区、不依赖中央服务器的方向继续有效。该纲领中暂缓的实时跨设备同步和团队协作，不因新增备份而视为已开放。

后续实施状态与实际验证范围单独记录于[首轮实现与构建记录](29_CLOUD_BACKUP_IMPLEMENTATION.md)，下文继续作为设计目标；不应将全部分期视为已完成。

## 目标与交付边界

保留本机优先、单教师使用方式，新增可选的个人网盘备份。备份包含已保存的作业、rubric、原稿、评阅、评分、私人笔记、历史和进度。支持在另一台安装 Labwise 的电脑恢复为独立副本，再继续批改。未保存输入、浏览器草稿、AI 密钥、OAuth 令牌和本机备份配置不进入备份。

1. iCloud Drive：用户选择已存在的本机 iCloud Drive 目录；Labwise 在其内建立专属备份子目录，系统负责云端传输。不模拟 Apple 登录，不使用非官方 iCloud API，不要求修改工作数据库位置。
2. OneDrive：同时提供客户端文件夹模式与 Microsoft Graph 账号模式。账号模式使用公共客户端设备授权，只申请 `Files.ReadWrite.AppFolder offline_access`；使用应用专属目录，无需 Labwise 中央服务器或客户端秘密。
3. 支持立即备份、应用运行期间的定时备份、查看历史、手动重试及恢复独立副本。关闭应用后不保证继续执行备份。
4. 本版不提供双向自动合并、多人协作、云端实时数据库、CloudKit、后台系统服务、网盘内直接编辑或自动切换工作区。

## 界面与操作

设置页新增“网盘备份”，分 iCloud Drive、OneDrive 客户端文件夹和 OneDrive 账号。文件夹模式通过本机绝对目录配置，提供 macOS iCloud 推荐路径；配置前明确备份包含私人笔记和学生原稿。账号连接显示微软验证码和官方登录地址，在本地轮询授权状态；不在 Labwise 输入微软密码。微软应用 ID 由维护者通过环境变量提供，未配置时仍可使用客户端目录模式。

每个目标独立选择关闭／15 分钟／60 分钟定时备份。保存配置不自动上传，启用定时即授权应用运行时上传已保存资料。立即备份前提醒保存编辑内容；定时任务仅处理已保存版本。状态区显示最近成功时间与最近错误；文件夹结果显示“已写入本机网盘目录，云端状态请查看网盘客户端”，Graph 完成响应才显示上传成功。

历史列出时间、设备／工作区来源及大小。用户选择恢复时明确确认包含私密资料、恢复为独立副本、原工作区保留、AI 密钥重新配置。恢复成功展示启动路径与说明。断开账号删除本机令牌与待授权状态，不删除云端历史；用户可在微软账号管理页撤销应用授权。

## 数据与实现

继续使用 `local_backup.py` 的 SQLite backup API、一致性快照、原稿校验、manifest 和严格恢复验证。不同步运行中的 SQLite、WAL、密钥文件或整个数据目录。首版保留 64 MiB ZIP／256 MiB 展开限额，在界面说明；大容量流式与增量备份另行设计。

新增 `cloud_backup.py` 统一管理目标配置、历史列表、备份、恢复、账号授权及周期任务。`pilot_backend.py` 分派 `/api/pilot/cloud/*`；`server.py` 启动周期检查并沿用本机来源验证；新增 `cloud-backup.js` 和样式接入设置页，纳入公开资源及安装包。

配置与运行状态放在 DATA 下的独立 JSON，不进入数据库备份。工作区 UUID 与设备 UUID 保存在本机配置，文件名为 `Labwise-<UTC时间>-<工作区>-<设备>-<随机值>.zip`，每次创建新对象，不覆盖或自动删除历史。支持恢复其他工作区的备份，但界面明确展示来源，不隐式覆盖或合并。

文件夹模式要求已存在的绝对父目录，拒绝与活动数据目录重叠的目标；在专属子目录写临时文件、flush/fsync 后原子发布。拒绝符号链接备份、路径穿越和非约定文件名。恢复前再次核对边界与大小，不信任浏览器提交的路径。

Graph 固定访问 `graph.microsoft.com/v1.0`；列出 app root 内符合格式的备份，处理分页。上传唯一文件名，核对返回大小；恢复必须先确认对象位于 app root，限制下载大小，再交由现有恢复验证。下载重定向时不把 Bearer 令牌发送到存储下载地址。网络失败只记录通用错误，不保存远端响应中的敏感内容。

设备授权后端保管 device code，浏览器只收到 user code 与官方 verification URI；按微软 interval 轮询并处理 pending、slow_down、取消、到期。刷新令牌和访问令牌仅存于内存，应用退出需重新连接，避免将 OAuth 秘密写入磁盘；后续可用系统钥匙串实现持久连接。断开与并发刷新需锁保护。账号模式仅针对微软全球云；世纪互联等国家云留待单独验证。

定时检查线程是守护线程，仅应用运行时有效；单次备份互斥，配置和账号操作有锁，失败不删除旧备份，周期后重试。使用单调时钟控制轮询／调度，不靠文件修改时间决定新旧版本。长时间停机后恢复运行不会补发所有错过任务。两个设备各自产生独立快照，历史不构成自动合并。

## 隐私与恢复

本版 ZIP 不具备应用级加密，不能称为端到端加密备份。用户按所在学校规则选择获准网盘；同步前明确包含学生原稿和私人笔记。AI 密钥与 OAuth 令牌保持设备隔离。备份历史不自动清理，容量由用户在网盘管理；不要把同步误删当成历史备份策略。

## 接入配置

维护者注册支持所需个人／组织账号的 Microsoft Entra 公共客户端，启用公共客户端流，配置委托权限 `Files.ReadWrite.AppFolder`。启动前设置 `LABWISE_ONEDRIVE_CLIENT_ID`（非秘密的应用 ID）。首次连接可能需要机构管理员同意。无注册 ID 不伪造可用状态；可先选 OneDrive 本机目录使用。冻结安装包的 ID 配置与正式签名发行另行验收。

官方依据（2026-11-04 核对；接口和机构策略仍须在实现时复核）：

- [微软设备授权流程](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)：公共客户端授权、用户验证码、轮询间隔及到期处理。
- [OneDrive 应用文件夹](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder)：应用专属目录和最小文件夹权限。
- [Graph 单次文件上传](https://learn.microsoft.com/en-us/graph/api/driveitem-put-content?view=graph-rest-1.0)：单次内容上传及返回对象；服务上限不等于本应用首期限额。
- [Apple iCloud 文档设计](https://developer.apple.com/library/archive/documentation/General/Conceptual/iCloudDesignGuide/Chapters/DesigningForDocumentsIniCloud.html)：系统文件传输、文档协调与原生容器要求。此资料为 Apple 历史指南，具体 API 须按目标 macOS SDK 验证。

真实 iCloud 上传／异机下载及真实 OneDrive 授权／学校租户需用户账号现场验收，不用模拟测试替代。验收结果写入独立版本记录。保持既有 Word 转换与打包改动。

## 实施基线与范围取舍

### 当前可复用的能力

- `app_paths.py` 已将程序资源和用户数据分离；安装版继续在本机资料目录运行，不能把 `LABWISE_DATA_DIR` 指向网盘来代替同步设计。
- `local_backup.py` 已使用 SQLite backup API 获取一致性快照，按快照中的引用收集原始报告、图像和预览，并生成 SHA-256 清单。
- 恢复机制已校验压缩包条目、引用文件和数据库完整性，在独立目录建立副本；进行中的分析会变为需人工重试的状态。
- `user-support.js` 已有下载备份、恢复入口，以及未保存输入提示。新增网盘设置应与这些入口相互链接，保留手动 ZIP 作为离线恢复路径。
- 工作区已有 `cloud_backup.py` 草稿，实施前须按本文逐项检查接口、线程生命周期和安全边界，不能以文件存在作为完成证据。

### 首期默认决策

1. 用户界面采用“网盘备份”，避免将快照传输描述为实时同步。
2. iCloud 首期覆盖当前 macOS 桌面交付；OneDrive 文件夹模式覆盖安装有客户端的目标电脑，账号模式先验证微软全球云。不能据此宣称整个应用已支持 Windows 或移动端。
3. 一个工作区可以配置多个备份目标，目标之间互不复制、互不删除；每次分别显示结果。
4. 默认关闭自动备份。可选 15 分钟或 60 分钟；应用运行时执行，不新增登录启动项或系统常驻服务。
5. 首期备份整个已保存工作区，不做“只备份某门课程”。选择性备份需要重新设计依赖收集和恢复语义，另行排期。
6. 首期保留现有容量限额、无应用级加密、不自动清理历史。界面必须如实呈现这些边界。
7. 换机采用“恢复副本 → 核对 → 主动继续批改”。首期不自动替换当前工作区，不在启动时自动覆盖本机较新的工作。

## 用户旅程与页面设计

### 首次配置 iCloud Drive

1. 教师进入“设置 → 数据与备份 → 网盘备份”，选择 iCloud Drive。
2. 页面说明将备份学生原稿、私人笔记及已保存的批改内容，密钥与未保存输入不包含在内。
3. 优先通过桌面目录选择器选择已有 iCloud Drive 文件夹；目录路径输入作为可校验的备用入口。浏览器的普通文件选择不能被当成获得后台目录写入权限。
4. 后端验证路径存在、可写、与活动资料目录隔离；创建并清理一个无学生内容的探测文件，只完成连接检查。
5. 保存位置后，由教师选择“立即备份”或主动启用定时备份。不得因选择文件夹就上传已有学生资料。
6. 完成后显示“备份已写入 iCloud Drive 本机目录，云端状态请查看 Finder”，并提供打开目录入口。

路径建议仅用于方便定位，不能硬编码为所有电脑的真实位置。退出 Apple 账号、目录不可用、文件仅在云端或权限变化时，保留本机工作并说明处理办法。若无法确认目标属于 iCloud，应标为“自选备份目录”，不把普通文件夹包装为已连接 iCloud。

在原生辅助层中评估 `NSFileCoordinator`、文件可用性和下载状态 API；通过 iCloud 原生容器接入则需单独完成 entitlement 与签名配置。首期选择用户目录不等于已接入应用 iCloud 容器，也不能承诺 CloudKit 能力。

### 首次连接 OneDrive

教师可选择“使用本机 OneDrive 文件夹”或“连接 OneDrive 账号”。文件夹模式复用上述步骤，并明确由 OneDrive 客户端上传。

账号模式首期沿用草稿中的设备授权方案，减少当前本机网页服务的 OAuth 回调配置；优先采用受支持的 MSAL 库封装授权。页面仅在教师点击连接后申请验证码，显示官方登录链接和有效期。教师在微软页面完成登录和授权，本机后台按返回间隔查询结果。

连接成功后显示账号／组织的可用标识、目标为 Labwise 应用目录、是否开启定时备份。获取展示信息不得暗中扩大文件权限；如果需要额外身份 scope，应在实施评审中列明。授权完成本身不上传资料。

首期若令牌仅保存在内存，页面必须说明“退出应用后需要重新连接”。重启后原定时计划进入“待重新授权”，不能显示为仍在保护资料。正式持续自动备份的后续条件是系统钥匙串持久化，并验证打包签名变化后的访问行为。

桌面正式版评估授权码＋PKCE 与系统浏览器交互，设备授权保留为可选路径；机构禁用设备授权时提供文件夹模式，不自动扩大权限或绕过组织政策。[微软授权码流程说明](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)

### 日常备份与查看历史

- 每个目标显示备份位置、计划、最近一次尝试、最近一次成功、待处理错误及本次资料大小。
- “本机已保存”“已写入网盘目录”“OneDrive 服务已接收上传”分别表达；Graph 成功不等于已在另一台电脑下载或完成恢复验证。
- 手动备份发现有未保存修改时，提示先保存；定时备份只读取已提交数据库的内容，不调用教师确认、不自动提交评分。
- 历史列表提供时间、来源工作区、来源设备、大小和恢复入口。时间按用户本地时区展示，文件名和清单使用 UTC；不能只靠修改时间判断哪台电脑内容更新。
- 若列表有分页，应可继续加载；若只取得部分历史，必须提示，不得把截断结果称为全部备份。
- 断开仅停止该目标并移除本机授权；网盘上的已有备份保留。删除云端历史留在网盘客户端处理，首期不开放自动清理。

### 换电脑恢复与继续批改

1. 新电脑先安装兼容版本 Labwise，选择同一 iCloud／OneDrive 目录或登录同一 OneDrive 账号。
2. 教师主动打开历史并选择备份；iCloud 占位文件需要先下载完成。不得用空文件或未完成下载当作可恢复资料。
3. 下载到本机临时目录，验证大小、格式、清单和数据库；展示来源及时间，说明恢复将建立独立副本。
4. 恢复完成后打开说明，关闭原工作区，再启动恢复副本。只展示独立目录路径不能称为已切换工作区。
5. 核对作业数量、批改进度与代表性报告，重新配置获准使用的 AI 密钥；不自动重启历史分析任务。
6. 恢复副本不继承旧设备的网盘配置与授权，启用备份时产生新的本机设备身份。沿用现有恢复格式时，也会形成新的备份工作区身份；界面应按来源分组，不假装原工作区身份已完整迁移。

两台电脑都继续修改会形成两个完整分支。首期恢复只能选择其中一个副本继续，不能把两份数据库自动合并，也不能以恢复“最新备份”来覆盖另一台电脑上的独有修改。

## 数据协议、接口和任务管理

### 首期备份协议

继续采用 `labwise-backup.v1` ZIP：数据库与被引用的资产组成一个不可变快照。清单中的 SHA-256 用于检查内容完整性，不等同于来源认证或加密。备份文件名使用 UTC 时间、工作区标识、设备标识和随机值；标识不包含学生姓名、课程标题或教师邮箱。

首期来源标识来自文件名，不要求修改现有 manifest。若要加入完整 `backup_id`、来源链、数据库 schema 版本、最小可恢复应用版本等元数据，应设计 v2 清单、读取兼容及迁移测试，不能无说明改变 v1 严格校验规则。

现有 v1 恢复只具备有限结构检查，不能据此保证任意版本兼容。首期正式验收先限定为同一应用版本间恢复，已知不兼容的备份须拒绝；跨版本恢复支持要有独立迁移证据。应用升级前保留旧版本及原备份。

原始报告、历史版本引用和评分细则快照必须一起恢复；未保存的浏览器输入、界面布局、问题反馈草稿和单独下载到外部目录的 PDF／Word 不属于完整工作区备份承诺。后续若增加导出文件归档，应建立独立目录与明确选项。

### 模块职责与接口草案

- `local_backup.py`：继续负责一致性快照、文件收集、校验与独立副本恢复。
- `cloud_backup.py`：负责目标配置、传输适配器、授权会话、历史和任务协调。文件夹与 Graph 共用备份产物，避免各自复制数据库逻辑。
- `pilot_backend.py`：分派本机 API，检查 provider、参数和操作权限。
- `server.py`／`app_runtime.py`：负责启动和停止调度器，确保同一资料目录只有一个调度实例。
- `cloud-backup.js` 与样式：负责设置与状态呈现；接入中英文界面、资源检查、macOS 打包和 Docker 清单。

接口沿用草稿 `/api/pilot/cloud/` 路径，全部为计划契约，不能作为已交付 API 使用：

- `GET status`：返回目标配置、是否已授权、容量边界和最近状态；不返回令牌。
- `POST configure`：保存 provider、目录与间隔，验证通过后生效，不触发立即上传。
- `POST connect / poll / disconnect`：启动、查询和停止 OneDrive 授权；本机后台持有设备码。
- `POST history`：按 provider 读取可用备份；接受明确的分页游标或返回加载范围。
- `POST backup`：对指定目标执行一次快照备份；重复点击不能创建并发操作。
- `POST restore`：只接受已列出的备份标识，重新验证目标边界，再建立独立恢复副本。

长时间传输不能阻塞整个本机 HTTP 服务。首期可使用有超时的工作线程；如交互请求超时但后台继续，必须返回或记录任务标识，允许查询结果，不能让用户因“超时”重复上传。文件名中不包含敏感信息。写操作沿用本机来源检查，目录和远端下载地址不允许由网页任意指定。

### 状态与并发

连接状态为“未配置／已配置／等待授权／可用／需要重新授权”；备份任务状态为“等待／生成快照／传输中／已写入本机目录／服务已接收／失败／取消”。恢复另外记录“下载／校验／建立副本／完成／失败”。关闭页面不会暗示任务已经停止。

每个活动工作区只允许一个备份或恢复操作；自动任务忙碌时跳过本次，手动请求返回明确状态。切换目录或账号不得改变在途任务的目标：任务在开始时固定 provider、目标、账号会话代次和快照标识。断开或切换账号后，旧任务结果不能写入新账号状态；不在全局配置锁内等待长时间网络操作。

调度以单调时钟推进，重启后重新计算下一次计划，不补发全部错过的周期。首期按周期失败后再尝试，手动重试随时可用；如果增加快速重试，则应使用有限次数、退避和服务返回的 `Retry-After`，避免失败循环。关闭应用时停止派发新任务，保留可恢复状态并清理本机临时文件。

## 异常、权限与数据保护

- 断网或网盘空间不足：保留已保存资料和历史备份，持续显示失败原因；最近成功时间不能被失败时间覆盖。
- iCloud 文件未下载／目录移走／Apple 账号退出：停止该目标，提示在 Finder 下载或重新选目录，不自动回退到一个普通本机目录并声称已上传。
- OneDrive 401／授权撤销：进入需重新授权；403／组织限制：说明权限不可用；429：遵循限流；传输失败不得删除上一份快照。
- 上传响应丢失：先查询本次唯一文件名判断结果；发现不完整对象不作为成功备份展示。文件大小核对仅能确认服务接收情况，内容可恢复性还需下载后清单校验。
- 文件夹发布：临时文件完整写入后原子改名；其他设备只列出最终命名文件，但仍需下载及校验。临时文件也可能被客户端上传，不能承诺网盘中完全没有临时对象。
- 恢复失败或取消：清理暂存，当前工作区保持可用；损坏 ZIP、异常压缩比、路径穿越、符号链接和引用缺失均拒绝。
- 两端修改：保留各自快照，不按云端修改时间静默选胜者。两个来源同时备份不会提供互斥保证；说明“一次只在一台设备继续工作”是使用约定，不是跨设备锁。
- 下载链接和分页：限定官方服务来源和 HTTPS，校验重定向，不把 Bearer 转发给预授权下载主机；预授权 URL、访问令牌、设备码及学生正文不进入日志。
- 范围与授权：首期整库备份包含私人笔记与学生原稿，配置时告知。若学校不允许个人网盘，该目标保持关闭，手动本机备份仍可使用。
- 加密与凭据：首期不承诺应用级加密、端到端加密或独立密码保护；后续加密必须同时设计恢复口令、密钥管理和丢失后的行为。不能将普通 ZIP 或网盘自身加密宣传为 Labwise 已实现端到端加密。

## 分期开发计划与完成条件

### P0：接入验证与协议冻结

交付：复核现有草稿、固定首期接口和 UI 文案，使用虚构资料完成 iCloud 目录写入／另一台 Mac 下载恢复，以及 OneDrive 最小权限下创建应用目录、上传、列出、下载的技术验证。

前置条件：可用的目标 macOS 环境、受控虚构样本、维护者注册的微软应用 ID，以及测试账号。不能让每位教师自己注册开发者应用。正式包应注入维护者的公开 client ID；环境变量仅作为开发与受控试用配置。

完成条件：记录实际授权 scope、个人账号和拟支持学校账号结果、iCloud 文件协调策略、下载状态识别边界，以及容量基线。Graph 通用端点文档列出的权限与 AppFolder 专项文档可能不完全一致，必须验证本方案实际端点在 `Files.ReadWrite.AppFolder` 下可用。失败时调整端点或回到文件夹模式，不默认申请全盘权限。

### P1：iCloud 与 OneDrive 文件夹备份

交付：目标选择、开关与间隔、立即备份、独立历史、目录写入状态、独立恢复、帮助说明和中英文文案。

完成条件：教师能在目标 Mac 上完成配置、备份、关闭重开、异机取得备份和恢复；故障不破坏本机工作区。应用退出后不运行的边界在界面可见。

### P2：OneDrive 账号模式

交付：受支持的授权流程、应用专属文件夹传输、分页历史、重新授权、断开、机构限制及网络错误处理。无需网盘客户端即可上传和恢复。

完成条件：真实个人 OneDrive 与拟支持的学校租户完成往返恢复验证；未验收的租户和国家云不列为支持范围。若仅内存令牌，则作为明确标注的试用体验交付；持久自动备份需完成系统钥匙串接入及安装包验证。

### P3：容量、持续连接与恢复体验优化

交付：移除 Base64 全量内存往返、流式生成与恢复、可取消后台任务、必要的分片断点续传、钥匙串凭据管理、版本兼容元数据和恢复副本启动入口。根据实际数据量再决定增量备份和保留策略。

完成条件：在选定容量基线上验证内存峰值、耗时、磁盘空间不足和中断恢复；不能只提高数字限额。使用上传会话前，重新核实其 AppFolder 权限和错误恢复行为。[Graph 上传会话说明](https://learn.microsoft.com/en-us/graph/api/driveitem-createuploadsession?view=graph-rest-1.0)

### P4：跨设备增量同步，单独立项

在真实使用证明需要后，再设计稳定工作区身份、记录 UUID、父版本、设备来源、修改日志与删除标记。不可变原稿按内容哈希传输；不同报告可以独立合并，同一报告的评分和评语冲突保留双方版本供教师处理。

该阶段需要解决离线修改、并发写入、重试幂等、误删恢复和版本迁移。网盘变更接口只能帮助发现文件变化，不能代替业务冲突处理；不能复用数据库文件覆盖来实现双向同步。

本规划按依赖顺序排期，不预设完成日期或把 P3／P4 作为首期交付承诺。

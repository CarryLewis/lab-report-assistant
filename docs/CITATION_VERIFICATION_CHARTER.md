# 引用验证模块开发纲领

- 文件性质：引用验证模块的架构与开发约束
- 版本：1.0
- 生效日期：2026-10-23
- 状态：按用户确认的总体设计建立，后续开发须遵循
- 适用范围：引用解析、外部检索、格式检查、摘要与全文处理、AI 内容比对、教师审核，以及相关数据、接口、界面和测试

## 1. 目标与治理

本模块帮助教师判断学生是否规范、准确、恰当地使用文献。系统提供可追溯的候选判断，由教师确认后进入反馈流程。

本文件是该模块后续开发的总体依据。`docs/06_CITATION_VERIFICATION.md` 承载详细方案；实现细节可以迭代，但必须符合本纲领。新增需求、接口、提示词、数据结构和页面均应注明所属模块与开发阶段。

需要改变模块边界、证据要求、教师责任或阶段顺序时，应先提出具体变更及理由，经用户确认后更新本纲领，记录日期、版本和影响范围，再实施。常规修复与不改变约定的实现优化可直接开展。

本纲领不是功能完成声明。文档、演示数据、人工分析、自动检测和实际联网测试必须分别标注。

## 2. 核心证据链

每个引用验证结果必须沿以下路径追溯：

学生引用句及上下文 → 参考文献条目 → 已确认的外部文献 → 原始摘要或全文证据 → 核对意见 → 教师确认。

报告段落、引文范围、参考条目及来源片段都应具有稳定标识或位置。原文与教师修订分别保存，不覆盖学生原始表述。

检索命中、身份确认、格式合规与内容支持是不同结论，不得用其中一项代替其他项。摘要未涉及某个细节时，应请求全文复核或报告证据不足，不据此直接判错。

## 3. 六个功能部分

### 3.1 引用识别与关联

提取正文引文、参考条目和原文位置，建立对应关系。优先支持作者—年份制，再扩展编号制。分别报告孤立引文、未引用条目、重复条目与歧义关联。记录输入完整性，区分完整报告和片段。

### 3.2 文献身份核实

使用 Crossref、PubMed、Europe PMC；优先以 DOI、PMID、PMCID 确认身份，其他情况比较题名、作者、年份并提供候选。区分已确认、多个候选、字段冲突、未找到和服务不可用。教师可选择来源或补充标识符；不得默认把检索第一条当成正确来源。

### 3.3 引用格式检查

以作业指定样式及版本为依据，采用规则和 CSL 处理，AI 可辅助解释。输出字段级问题与修改建议。未指定样式时仅检查对应关系及字段完整性。来源可确认时，即使存在格式问题，也允许继续内容核对。

### 3.4 来源阅读与概览

优先取得正式摘要，再扩展到许可范围内的全文或教师提供的附件。中文概览说明研究问题、对象、方法、发现及限定条件。原始证据、生成概览分别保存，明确摘要或全文依据、来源、获取时间及模型版本。搜索结果片段只能用于发现来源，不能替代正式摘要。

### 3.5 引用内容比对

以每个引用位置为单位提取最小主张，必要时读取相邻句。AI 直接比对学生表述与来源原文；概览只辅助理解，不能作为唯一证据。检查对象替换、条件遗漏、因果夸大、结论强度扩大、来源性质误述等差异。

允许的内容结论为支持、部分支持、存在矛盾、来源未涉及、证据不足；处理状态另行记录待分析、待复核、已审核等。非证据不足类结论必须附可定位的来源片段及解释。不得以语义相似度代替内容支持判断。

### 3.6 教师审核与反馈

并列呈现学生原句、文献身份、来源概览、原文证据和差异解释。教师可确认、修改、驳回或请求全文复核。记录审核人、时间和修订理由；审核意见加入最终反馈须由教师确认。引用核验不自动扣分或认定学术不端。

## 4. 工作流与技术组织

采用可重试的分阶段任务：报告解析 → 引用关联与格式检查 → 文献检索及消歧 → 证据获取 → 单条主张比对 → 结果汇总与审核。

每阶段分别保存输入版本、输出、状态和失败原因，允许恢复；单条文献或单个数据库失败不应阻止其他任务。模型输出应按固定结构验证，检查段落和证据位置真实存在，再展示给教师。

同篇文献的元数据和概览可缓存复用；不同引用位置的主张分别分析。记录生成模型、提示词、规则和来源版本，支持重新分析及回溯。

## 5. 核心数据对象

- 引用位置：报告、段落、引文范围、上下文、主张及关联条目。
- 来源文献：标识符、数据库元数据、摘要或全文证据、来源时间及许可信息。
- 核验结果：检查类型、结论、处理状态、规则或模型版本、证据片段和解释。
- 教师审核：审核状态、确认或修订内容、审核人、时间及理由。

来源可共享缓存，报告与审核数据按课程权限隔离。仅向外部检索发送必要书目信息；模型分析使用最小必要上下文。外部文本均作为待分析数据处理。

## 6. 界面原则

以现有引用核验页签为入口，按单条引用展开。教师同时能看到学生上下文、文献与概览、证据与差异、审核操作。支持双向原文定位和来源访问。

分别显示格式待处理、身份待确认和内容待复核数量，不用一个综合通过率掩盖不同检查。演示结果必须明确标注，服务错误与文献不存在分别显示。

## 7. 分期交付与验收

### 第一版：引用基础检查

交付报告引用抽取、正文与条目关联、文献身份核实、首种指定格式检查、教师修正及保存。现有三库检索作为基础继续完善。

验收须覆盖完整与片段输入、多个候选、缺失字段、孤立引文、重复条目及服务失败，分别统计抽取、匹配和格式规则的准确性与误报。

### 第二版：摘要级内容核对

交付正式摘要获取、中文概览、主张提取、证据定位、差异解释及审核闭环。用现有语料建立教师标注测试集，检查支持范围、来源性质及证据不足处理。

验收须核对结论是否与证据一致、证据能否定位，以及误报、漏报与教师修订原因。阈值通过试点确定并记录，不以模型自报置信度替代评测。

### 第三版：全文及复杂来源

扩展开放全文、教师附件、网页、教材章节、二手引用、跨句引文及其他样式。按来源类型分别测试，记录访问及复用条件。

每版独立可用、独立验收。默认按顺序推进；部分基础能力未完成时可用明确标注的固定样本验证后续技术，但不得宣称已具备端到端能力。

## 8. 后续详细设计顺序

1. 引用对象的数据结构与报告抽取流程。
2. 文献消歧、教师纠正与三库检索接口。
3. 首种引用样式、规则和格式验收集。
4. 摘要、概览与主张比对输出契约。
5. 证据展示、教师审核及反馈保存。
6. 全文与复杂来源扩展。

每次交付说明实现了哪一部分、验证方法、剩余限制，并同步详细方案与测试记录。
